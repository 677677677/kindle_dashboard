# Dashboard 架构说明

这是时间 Dashboard 的只读展示层。它只消费版本化快照，不直接读取设备、日历或数据库。

```text
dashboard/
├── app/
│   ├── globals.css    # 800×600 横版灰阶 Kindle 视觉与窄屏回流
│   ├── layout.tsx     # 中文页面元数据和根布局
│   └── page.tsx       # 服务端读取真实快照并输出完整首屏，不承载统计推导
├── lib/
│   └── snapshot.ts    # snapshot-v1 类型守卫、状态文案与格式化函数
├── public/            # 仅存放确有使用的静态资源
└── .openai/           # Sites 项目元数据
```

依赖方向保持单向：`本机 snapshot.json → page.tsx 服务端渲染 → Kindle HTML`。页面无业务写入；时间合并、日历占用、剩余时间计算和数据源状态均由 Python 快照层确定。日历计划使用 `planned` 状态，不得伪装成已发生的活动。Kindle 不依赖客户端 JavaScript 即可看到完整快照；快照缺失时只显示不可用状态，禁止回退到演示数字。

`page.tsx` 的 `DayAxis` 在原来的单条 01:00—次日 01:00 横轴内叠加过去的 rednote/bilibili 与未来的匿名预留，仅负责时间到像素的映射；保留刻度与简短 App 图例，不显示解释性备注。`snapshot-v1.dayAxis` 由后端生成，预留从完整窗口裁至现在之后，10 分钟手机过滤不得影响每日总量。

首页采用800×600横向布局：上部日期、剩余及固定安排；中部全宽单轴；下部左侧全天环图，右侧七日趋势。`allocation` 和 `history` 由后端统一计算，前端只把秒数和百分比映射成SVG几何。手机和阅读趋势共用零起点百分比轴，空值断线，单点保留标记；全部缺失时只显示日期坐标和空态，禁止绘制演示曲线。删除此刻与设备明细不影响Kindle采集。完整SVG在服务端生成，零客户端脚本仍可读。

未确认全天完整的非零历史记录可显示，页面提示可能不完整；无证明的零仍留空。

原单轴保留未来日历占用，日程摘要复用图例所在行，不新增拥挤的大面板。页脚优先显示手机待同步／日历缓存等来源异常，再显示历史完整性摘要；快照生成成功不能覆盖源端停更状态。

## 独立桌面组件

```text
dashboard/
├── app/api/widget-snapshot/route.ts # 固定本机端点的只读、禁缓存代理
├── app/widgets/
│   ├── [panel]/page.tsx             # 四块独立桌面页面的服务端首屏
│   ├── widget-panel.tsx             # 30秒更新、缓存和来源状态
│   └── widgets.css                  # 桌面专用透明自然色样式
└── lib/
    ├── dashboard-ui.tsx             # Kindle和桌面共用时间值、单轴、环图
    └── load-widget-snapshot.ts      # 四秒超时的本机快照加载
```

依赖为 `本机 snapshot-v1 → 只读加载/代理 → widgets → desktop skins`，不写数据、不重算时间、不新增采集。四页为 `remaining`、`overview`、`allocation` 和 `axis`；尺寸和位置由桌面承载层配置，底部轴基准980×70。

根布局不输出meta定时刷新；仅Kindle首页正常和不可用分支输出300秒刷新，由React提升到head，保留无脚本运行。桌面服务端完全不输出刷新标签，客户端每30秒只更新数据。所有桌面页显示数据生成时间；离线保留最后快照并标缓存，来源异常、12分钟过期和跨日旧记录不得被HTTP成功掩盖。透明样式限定在 `.desktop-widget` 容器，不改变Kindle界面；公开首页原有七日趋势保持不变。

- 2026-11-02：新增桌面只读视图、共享展示模块和快照代理，不包含个人部署数据。

`dashboard/.openai/hosting.json` 是现有 `vite.config.ts` 所需的可公开构建占位配置，仅含 `d1: null`、`r2: null`，不含绑定、账户信息或密钥。不得将实际部署绑定或其他本机 `.openai` 文件混入该源包。
